## 1. Project Overview

### 1.1 Project Summary

The design is an island-style embedded FPGA generated by FABulous and hardened on ICS55 for an OpenECOS MPW die. The array is 13 columns by 12 rows of 151 hard tiles of 12 types, abutted into a 947.0 × 884.8 µm block (837,906 µm²). It carries 800 logic cells (`FABULOUS_LC`, a 4-input LUT with flip-flop and carry), 5 hard 8 × 8 multiply-accumulate blocks (`MACC_8x8_20`) and 40 bidirectional user IO. Configuration is frame-based. A bitstream addresses individual frames, so the fabric supports both full configuration and partial reconfiguration of any subset of frames while the rest of the fabric keeps its configuration.

The hardened top level `eFPGA_top` places the array with the configuration controller and its four loaders (UART, bitbang, SPI, 32-bit parallel) in one 999.0 × 912.6 µm block (911,687 µm²).

Each tile type is hardened standalone by ECC from synthesis to a routed macro with abstract LEF and extracted Liberty. The array is then assembled by abutment rather than by a flat place and route: the 32,404 nets that join one tile to the next are connected by coincident pins and are withheld from the router. Before any fabric-level run, `task check` proves that every link `Fabric/eFPGA.v` declares across a tile seam meets at one coordinate on both tiles. The `eFPGA_top` run then routes only the 2,748 nets of the controller, the IO and the configuration buses.

Completed for this tapeout are the RTL, the 12 hardened tile types (all DRC 0 and iLVS 0), the abutment plan with every seam link checked, the hardened `eFPGA_top` with DRC 0, signal iLVS exact and setup and hold closed at 100 MHz on the configuration clock in all six full-chip STA corners. Not yet done are a mask-ready GDS (the ECC GDS holds every tile and standard cell as an abstract), a pad ring and seal ring for the MPW die, a functional simulation against this commit and a timed user design. Block RAM is excluded from this variant and exists only in the `bram` variant.

### 1.3 Design Highlights and Use Cases (Optional)

It is built by abutment of hardened tiles, which bounds each tile ECC run to one tile of at most 3,716 instances (`MACC`) and the top run to 2,586 standard cells around 151 fixed macros, instead of one flat run of 237,316 instances.

Measured on one `LUT4x8_ha` 614 configuration latches take 39.6% of the die and 345 `MUX4` plus 32 `MUX2` routing switches take 33.3%. Configuration storage and routing switches built from standard cells therefore set the logic density, not the column mix. The fabric runs at 955 logic cells per mm² (95.5% core utilisation) of array and 877 per mm² of `eFPGA_top`.

## 2. Design Description

### 2.1 System Architecture

The top module is `eFPGA_top`. `flow cli integrate` generates it (`flow/topwrap.py`, called from `flow/integrate.py`) as a flat netlist of 151 tile macros and the configuration logic, written to `build/nobram/top/rtl/eFPGA_top.v`. Its ports are identical to the hierarchical `fabrics/nobram/Fabric/eFPGA_top.v`, which instantiates the array `eFPGA` (`fabrics/nobram/Fabric/eFPGA.v`). The configuration logic is `config_frontend`, which merges four loaders into one word stream, and `fabric_config`, which turns that stream into frame data and frame strobes.

`eFPGA` is the 13 × 12 grid set by `fabrics/nobram/fabric.csv`:

| Column | Width (µm) | Tile types, top to bottom |
|---|---:|---|
| 0 | 28.8 | `NW_term`, `W_IO` × 10, `SW_term` |
| 1–5 | 82.6 each | `N_IO`, `LUT4x8_ha` × 10, `S_IO` |
| 6 | 70.8 | `N_term_MACC`, `MACC` supertile × 5, `S_term_MACC` |
| 7–11 | 82.6 each | `N_IO`, `LUT4x8_ha` × 10, `S_IO` |
| 12 | 21.4 | `NE_term`, `E_IO` × 10, `SE_term` |

Core rows are 84.0 µm and the two terminator rows 22.4 µm, so the array is 2 × 22.4 + 10 × 84.0 = 884.8 µm tall. Each tile holds its BELs, a switch matrix and its configuration latches. Routing wires of span 1, 2, 4 and 6 (`E1BEG`, `E2BEG`, `EE4BEG`, `E6BEG` and their other directions) cross each seam, and the configuration buses `FrameData` (384 bits, 32 per row) and `FrameStrobe` (260 bits, 20 per column) enter the array on its west and south edge tiles.

In `eFPGA_top` the array's lower-left corner sits at (50.0, 24.6) µm. The controller occupies a 48 µm channel on the west side and a 22.4 µm strip on the south side, and the array sits one 1.4 µm row above the strip so the strip's top rail does not touch the tiles.

The boundary of this design is `eFPGA_top`. No third-party IP is instantiated beyond the open-source RTL in Section 11.2; the BELs are FABulous primitives (`FABULOUS_LC`, `MACC_8x8_20`, `IOBUF`, `GBUF`, `SYS_RESET`) and all tiles are the classic library of `FPGA-Research/fabulous-tiles` at `5809cdf`.

### 2.2 Operation

Operation has two phases, configuration and user mode.

Configuration starts when `resetn` is released. A host streams 32-bit words into one of four loaders: `config_UART` on `Rx`, the bitbang port on `s_clk` and `s_data`, a write-only SPI mode-0 slave on `spi_sck`, `spi_cs_n` and `spi_mosi`, or the parallel port `SelfWriteData[31:0]` with `SelfWriteStrobe`. `config_frontend` takes words from them in the priority UART, bitbang, SPI, parallel. `fabric_config` waits for the start word `0xFAB0FAB1`, then reads a header word and 12 data words per frame, row 11 first and row 0 last. After the last data word it raises the `FrameStrobe` of the addressed frame in the addressed column, and each tile's latches in that frame capture `FrameData`. `ConfigBusy` is high while the FSM is out of idle. `Configured` is cleared by the start word and set by the desync header. `ComActive` reports UART reception, and `ReceiveLED` toggles on UART, bitbang or SPI activity.

The frame is the unit of configuration. One frame is 32 bits in every row of one column, and each tile holds up to 20 frames, 640 bits, of which `LUT4x8_ha` uses 614. A header word carries the column in bits [31:27], a desync flag in bit 20 and a one-hot frame mask in bits [19:0]. `fabric_config` raises `FrameStrobe` only in that column and only for that frame, so every other latch in the fabric keeps its value. A full bitstream writes all 20 frames of every column. A partial bitstream is the same format carrying only the frames of the region being changed, followed by the desync header. Because the user clock reaches the fabric through `GBUF`, separate from `CLK`, logic outside the rewritten frames keeps running during a partial reconfiguration. Logic inside the addressed frames sees its latches transparent while `FrameStrobe` is high, so the user design has to hold that region idle or in reset during the write. Partial reconfiguration follows from the RTL structure and has not yet been demonstrated in simulation.

In user mode the configured LUTs, flip-flops, `MACC` blocks and switch matrices implement the user circuit. The user clock enters on a `W_IO` input, is routed by configuration down the west column into `SW_term`, and leaves its `GBUF` BELs on `N_GBUF` wires up every column and `E_GBUF` wires along the bottom row, with one clock buffer per tile hop. `SYS_RESET_RESET_top` passes unregistered to the fabric as a routable reset.

Cycle counts depend on the user circuit and are not a property of the fabric.

### 2.4 Register or Command Definitions (Optional)

The fabric exposes no memory-mapped registers. It is programmed with a FABulous bitstream of 32-bit words. The table is read from `Fabric/fabric_config.sv`, `Fabric/config_frontend.v`, `Fabric/config_UART.v`, `Fabric/bitbang.v` and `Fabric/config_spi.v` at `92674fb`. Full and partial bitstreams use the same commands; a partial one contains fewer header and data groups.

| Address/Command | Name | Access | Reset value | Bit-field definition | Access side effects |
|---|---|---|---|---|---|
| `00 AA FF` + command byte | UART header | W | N/A | Command bit 7 selects hex (1) or binary (0) mode in the default auto mode | Starts a UART load; `ComActive` goes high |
| `0xFAB0_FAB1` | Start word | W | N/A | Fixed pattern | Moves `fabric_config` from idle to header; clears `Configured`; `ConfigBusy` goes high |
| Header word | Frame select | W | N/A | Bits [19:0] one-hot frame, bits [31:27] column, bit 20 desync flag | Selects one frame in one column; the next 12 words are its data |
| Frame data words | Frame data | W | N/A | 32 configuration bits for one row, row 11 first and row 0 last | After the 12th word the column's `FrameStrobe` pulses and the latches capture the frame |
| Header with bit 20 set | Desync | W | N/A | Bit 20 set | Returns `fabric_config` to idle, sets `Configured`, ends configuration |
| Bitbang control `0xFAB1` / `0xFAB0` | Bitbang on/off | W | N/A | 16-bit control word shifted on `s_clk` falling edges | `0xFAB1` latches the 32 data bits shifted on rising edges as one word; `0xFAB0` releases the port |
| SPI word | SPI data | W | N/A | 32 bits shifted in on `spi_sck` rising edges while `spi_cs_n` is low | Each complete word enters the stream |

The FABulous bitstream generator writes the header `00AAFF01000000010000000000000000FAB0FAB1`, so a generated `.bit` file can be sent unchanged over UART in binary mode, or word by word over bitbang, SPI or the parallel port.

### 2.5 Clocks and Resets

`CLK` clocks the configuration logic only. The top run constrains it at 10 ns (100 MHz, `fabric.frequency_mhz` in `Fabric/ecc_config.toml`), and the configuration logic closes setup and hold at that period in every corner (Section 6.3). The UART divisor `ComRate` keeps its default of 217, which gives 115,200 baud at 25 MHz and 458,716 baud at 100 MHz; 115,200 baud at 100 MHz needs `ComRate` = 867. Bitbang and SPI are sampled on `CLK` and do not depend on its frequency. `resetn` is the active-low reset of the configuration logic.

The fabric has no clock port because `fabric.csv` sets `DisableUserCLK`. Up to four user clocks enter on `W_IO` inputs and are buffered by the four `GBUF` BELs in `SW_term`, then by one clock buffer in every tile they cross. The user-mode clock frequency is not measured (Section 3.2).

`SYS_RESET_RESET_top` has no fixed polarity; the configured user design decides how to use it.

Minimum reset duration, reset release requirements and power-up sequencing are not specified: [to be taken from `fabric_config` and the MPW board's reset circuit].

### 2.6 Device Programming

Device programming is the current plan and is not yet implemented or verified. The package and test-board information for the MPW die has not been received. This section will be completed once it is available.

The plan reuses the bring-up flow of the wafer.space gf180mcu FABulous FPGA, `github.com/mole99/wsrun1-fpga-bringup` (commit `81a9a99`, Apache-2.0), as far as possible. That flow compiles user designs with Yosys `synth_fabulous`, then `nextpnr-generic --uarch fabulous`, then the FABulous bitstream generator, and loads the result from an RP2040 Raspberry Pi Pico running MicroPython.

Parts expected to carry over unchanged are the per-design `Makefile` flow, the bitstream format (the same `FAB0FAB1` start word and desync bit 20 that `fabric_config` expects), the Pico file layout and upload script structure, and the generic test designs (`counter`, `passthrough`, `all_ones`, `all_zeros`).

Parts that have to be replaced with this fabric's versions:

1. The nextpnr model and bitstream specification, taken from this build's `fabrics/nobram/.FABulous/` (`pips.txt`, `bel.v3.txt`, `bitStreamSpec.bin`).
2. The IO constraint file and `top_wrapper.v`, rewritten for this fabric's 40 `IOBUF` BELs; the gf180 wrapper targets four IO per `W_IO` tile.
3. The techmaps, without the register-file and SRAM mappings this fabric has no tiles for.
4. The Pico upload routine. The gf180 chip is loaded over SPI with `FPGA_MODE`, `FPGA_BUSY`, `CS_N`, `SCLK` and `MOSI`. This fabric's SPI loader takes `spi_cs_n`, `spi_sck` and `spi_mosi`, and `ConfigBusy` and `Configured` take the place of the busy flag, so the routine changes in its pin set rather than its protocol. Bitbang and UART remain fallbacks; UART needs `ComRate` matched to `CLK` (Section 2.5).
5. The Pico pin assignment, which depends on the MPW test board.

## 4. IP Reuse and Standardization

### 4.1 Reuse Objectives and Use Cases

- [ ] Shared infrastructure within an MPC, or a reusable module for designs submitted through an MPW shuttle, such as standard I/O, clock and reset, configuration, test, or bus-connectivity logic.
- [ ] An interface controller between a user design, shared platform infrastructure, and chip-level I/O, providing protocol conversion, register access, or control functions.
- [x] A standalone digital IP block, hard macro, logic tile, programmable fabric, accelerator, processor, or peripheral.
- [ ] A design intended only for validation in this tapeout, with no current plan for reuse across projects.

The fabric is reusable at three levels. Another project can take the hardened `eFPGA_top` as one block with its configuration controller, take the abutted `eFPGA` array and supply its own controller, or take the 12 hardened tile types and abut a different grid from them.

Fixed for reuse are each tile's die size, its pin order and pin coordinates along each edge, the signal layers (MET3 on east and west edges, MET4 on north and south edges), the PDN layers and the stripe positions. Abutment only works if facing edges agree, and `flow check` refuses a plan where any link fails to meet at one coordinate.

An integrator may change the grid in `fabrics/<variant>/fabric.csv` (column count and order, row count), as long as every column keeps one width and every row one height, and the configuration parameters that follow from it. A new grid means regenerating `eFPGA.v` and each `io_pin_order.yaml` through FABulous and re-running `task plan`, `task check`, `task harden` and `flow cli integrate`. Existing tiles need no re-hardening unless a die changes.

### 4.4 Standard Interfaces and Integration

1. A user design reaches the fabric through its 40 IO bits. The fabric is configured from a host over SPI, UART, bitbang or the parallel port, not through a bus.
2. Not applicable. The fabric is not an interface controller. All four loaders sample their inputs on `CLK`; `s_clk` and `spi_sck` are sampled rather than used as clocks.
3. The top level has to provide `CLK`, `resetn`, at least one loader, `SYS_RESET_RESET_top`, the 40 IO bits, and a user clock on one of the `W_IO` inputs. Unused loader inputs are tied to their idle level.
4. When `eFPGA_top` is used as a block, its die, its 166 pin positions and its power stripes are fixed. When tiles are re-abutted, every tile die, every edge pin offset, the signal layers and the stripe positions are fixed, and `flow check` enforces them.

### 4.6 Single Entry Point and Reproducibility

The build runs as five stages in order, each stopping at the first failure:

    task plan VARIANT=nobram        # size every tile and place every pin, writes build/nobram/fabric_plan.json
    task check VARIANT=nobram       # test the plan's wiring properties, no EDA tool
    task harden VARIANT=nobram      # one ECC run per tile type, synthesis to macro
    python3 -m flow.cli --variant nobram integrate   # harden eFPGA_top around the fixed tiles
    build/nobram/fullsta/{prepare.sh,run.sh}   # full-chip OpenSTA, six corners

Hardening all 12 tile types took [time] on 2026-10-17. The integrate run took about 64 minutes, 57 of them in ECC's 13-corner STA. Both should run detached under `setsid nohup`, with logs in `build/nobram/logs/`. Full-chip OpenSTA takes about 8.5 minutes and 2.7 GB per corner.

Four steps cannot be reproduced from a clean checkout today:

1. ECC `main` at `14be467` needs two uncommitted working-tree edits, a Nix flake override for boost and a `YOSYS_TECHMAP_FILES` block in `yosys_synthesis.tcl`. The second is requested upstream as ecc#302.
2. Regenerating RTL and pin orders needs the two FABulous checkouts in Section 4.2.
3. The PDK's liberty and GDS directories are fetched by `make` in `pdk/` from a GitHub release, not by `git submodule update`.
4. The full-chip STA scripts live under the gitignored `build/`, and `top_full.v` needs `$` renamed to `_DOL_` after `write_v.tcl`, because iRCX writes `$` unescaped and OpenSTA rejects it.

## 5. Design Verification

### 5.1 Verification Environment

Verification of this commit is structural, physical and timing-based; its functional simulation predates two clock changes. Six checks run:

1. `task check` tests the fabric plan against `Fabric/eFPGA.v`. Every link that `eFPGA.v` declares across a seam has to meet at one coordinate on both tiles. No EDA tool is involved.
2. Per-tile signoff runs inside ECC: iEDA DRC on the routed layout, iLVS comparing the routed DEF connectivity with the synthesised netlist, and 13-corner iSTA.
3. The `eFPGA_top` run refuses a tile whose LEF pins differ from the ports the netlist expects, fixes all 151 tiles at their planned coordinates, then runs the same DRC, iLVS and 13-corner iSTA on the top.
4. Full-chip OpenSTA reads the `eFPGA_top` netlist written from the filler DEF (the only view carrying the 32,404 tile-to-tile nets), the 12 tile netlists and the per-instance tile SPEF, and times the configuration clock and the user clock at six corners.
5. A bitstream simulation (Yosys, nextpnr-generic and Icarus Verilog) loads `sequential_16bit_en` into `eFPGA_top` through the parallel port and compares all 40 IO bits against a reference counter.
6. A cocotb test (`Test/config/test_config_frontend.py`) is parametrised over the UART, bitbang, SPI and parallel loaders.

## 7. Layout

The layout of record is the routed `eFPGA_top` DEF, `build/nobram/top/default/filler_ecc/output/eFPGA_top_filler.def.gz`. Its die is 999.0 × 912.6 µm. ### 9.3 Value to the Open-Source Community

To the best of the authors' knowledge, this project is the first fully open FPGA taped out on the open ICS55 55 nm process. Every layer of it is open. FABulous generates the fabric, the tiles come from the open fabulous-tiles library, and ECC synthesises, places, routes and signs off every tile and the top level on the open ECOS PDK. The project fills a gap in the open 55 nm ecosystem and adds a complete, verified programmable-logic example to the open-source chip ecosystem built around the ECOS platform.

The project provides reusable IP for this process node. The 12 hardened tile types have frozen dies, fixed pin orders and a PDN that joins by abutment. A later project can take the hardened `eFPGA_top` as one block, or re-abut the same tiles into a fabric of the size its own die allows without hardening anything again. The baseline specification, deliverables and acceptance status that make this reuse possible are set out in Sections 4.3, 4.5 and 4.7.

The project also lowers both the threshold and the risk of chip design. A custom ASIC is fixed at fabrication, so a design error or a change in project requirements means another tapeout. Logic mapped onto this fabric is corrected or changed after fabrication by loading a new bitstream, and partial reconfiguration changes one region while the rest keeps running. A research group that needs custom hardware for its own scientific work, such as an experimental accelerator, an instrument or sensor interface, or a teaching platform, can use the fabric as delivered or generate a custom fabric for its application from the same open flow at this node.

By opening the complete path from fabric generation to signed-off layout, the project makes chip design accessible to more universities, research teams and individual developers. It supports open sharing, collaborative development and self-directed innovation across the open-source chip ecosystem at 55 nm.

#### 9.3（中文版）开源社区价值

据我们所知，本项目是首个在开放的 ICS55 55 纳米工艺上流片的全开源 FPGA。项目从架构到版图全链条开源：FPGA 架构由 FABulous 生成，逻辑单元（tile）来自开源的 fabulous-tiles 库，每一种 tile 以及顶层均在开源的 ECOS PDK 上由 ECC 完成综合、布局、布线与签核。本项目填补了开放 55 纳米工艺生态在可编程逻辑方面的空白，为以 ECOS 平台为核心的开源芯片生态贡献了一个完整且经过验证的可编程逻辑实例。

本项目为该工艺节点提供可复用的 IP。12 种已完成物理实现的 tile 具有固定的尺寸和引脚顺序，其供电网络通过拼接（abutment）即可直接连通。后续项目既可以将已完成物理实现的 `eFPGA_top` 作为一个整体模块直接集成，也可以根据自身芯片面积，将同一套 tile 重新拼接为不同规模的 FPGA，无需重新进行物理实现。支撑上述复用的基线规格、交付物与验收情况详见第 4.3、4.5 和 4.7 节。

本项目同时降低了芯片设计的门槛与风险。定制 ASIC 一经流片，功能即被固定；一旦出现设计错误或项目需求发生变化，就必须重新流片。而映射到本 FPGA 上的逻辑，在芯片制造完成后仍可通过加载新的比特流进行修正或更改；借助部分重配置功能，还可以在其余逻辑持续运行的同时，仅对其中一个区域进行更新。需要为自身科研工作定制硬件的研究团队，如开发实验性加速器、仪器或传感器接口以及教学平台，既可以直接使用本 FPGA，也可以基于同一套开源流程，在该工艺节点上生成面向自身应用的定制化 FPGA。

通过开放从 FPGA 架构生成到签核版图的完整链路，本项目让更多高校、科研团队和个人开发者能够参与芯片设计，助力 55 纳米开源芯片生态的开放共享、协同发展与自主创新。

### 9.4 Suggestions for the Platform and Flow

1. ECC has no hook for a user techmap before its `flatten`, so FABulous `my_buf` buffers were synthesised into net aliases until `yosys_synthesis.tcl` was patched (ecc#302).
2. The file-driven IO placer (`io_placer.mode = "file"`) is on ECC `main` only, not on the latest tag `v0.1.0-alpha.12`. A tagged release that includes it would remove the need to build from source.
3. ECC's harden step writes `eFPGA_top`'s GDS as the same pin and OBS abstract as its LEF, and its timing model holds 2 arcs, so neither the routed layout nor the configuration-port timing reaches the harden outputs.
4. iRT has no way to mark nets connected by abutment. On the 122-tile `bram` fabric, 27,390 such nets drove the shape database to 49 GB before routing started, so the top run withholds them and restores them unrouted.
5. The standard cells in iEDA's GDS are LEF abstracts, which makes a whole-layout DRC of a hardened block meaningless and leaves the GDS merge to the user. A flag to stream real cell layouts would help.
6. iRCX writes `$` unescaped in SPEF and netlist names, which OpenSTA rejects.
7. The MPW die-size, pad-ring and seal-ring rules are not public, and the PDK ships no seal ring.

## 10. Lessons Learned and Future Work (Optional)

### 10.1 Lessons from Design and Verification

Checking abutment before any EDA run paid off. `task check` and the stale-die guard in `harden` refuse a broken plan and a plan older than its `[die]` tables within seconds, instead of after a full harden.

Detailed placement decided routability on the dense tiles. With DreamPlace's detailed placement off, `LUT4x8_ha` at 0.93 core utilisation oscillated between 2,134 and 2,643 violations over nine detailed-routing iterations. With it on, violations went 687, 72, 21, 3, 0.

Cell area, not instance count, ordered the ABC strategies. `AREA 5` gives 5,817.0 µm² on `LUT4x8_ha` against 5,882.0 µm² for the default `DELAY 4` (measured 2026-09 on the earlier toolchain), and that difference is what lets the 82.6 µm die route clean.

Per-tile STA cannot see the global clock. Every tile passed the `GBUF` clock through as a wire, so after abutment each global clock was one net of fanout 345 driven by one XOR gate. Only full-chip STA with per-instance tile SPEF exposed it, and one buffer per tile hop fixed it.

### 10.2 Physical Implementation Issues

1. **LUT column width.** The routing floor for `LUT4x8_ha` is 82.6 µm. At 81.8 µm placement reaches 0.9888 of the placeable area and three DRC violations remain after nine detailed-routing iterations. The fabric is sized around this floor, which gives a column quantum of 82.6 µm.
2. **Boundary buffers.** ECC's synthesis flattened every FABulous `my_buf` into a net alias. A techmap onto `BUFX1H7L`, applied together with a mux map onto `MUX4X1H7L` and `MUX2X1H7L`, keeps the 288 buffers per tile for about 1% of cell area. The fix lives as an uncommitted edit in the ECC checkout.
3. **Top-level routing.** The 32,404 tile-to-tile nets are withheld from iRT and restored unrouted, so the DEF carries them connected by geometry only. A planned alternative separates the tiles by a 1.4 µm gap and writes each seam net as one straight pre-routed wire on its pin's own layer, which makes every connection explicit in the DEF and lets the power stripes be bridged the same way. The double-height `MACC` breaks the straight-wire case on its upper half and needs a re-harden at 168 µm plus the gap, or iRT jogs on those nets.
4. **Global placement on the top.** Legalise-only placement piles every standard cell into one corner; global placement converges only with `place.target_overflow = 0.15`.
5. **Timing.** No user-mode clock path has been timed, and no step repairs slew or capacitance violations (Section 6.3).

### 10.3 Planned Improvements

The next revision should produce a mask-ready GDS with the pad ring and seal ring, rerun the bitstream simulation on this commit, demonstrate partial reconfiguration in simulation, match `ComRate` to the 100 MHz `CLK` and time a routed user design across the tiles' extracted Liberty. It should also repair slew and capacitance violations, commit the full-chip STA scripts to the repository, and fix the ECC build so it needs no uncommitted edits.

## 11. Additional Information

### 11.1 Known Limitations

- User-mode Fmax is unmeasured; the only tile-level figure (`sta_frequency_mhz` 23 on `LUT4x8_ha`) is a switch-matrix feedthrough, not a user clock.
- The last bitstream simulation passed on 2026-09-28, before the MACC clock buffer and the GBUF hop buffers; this commit has not been simulated. Row 0 (`N_IO`) configuration has not been shown to work.
- `ComRate` is 217, which gives 115,200 baud at 25 MHz but 458,716 baud at the 100 MHz `CLK` the top is constrained for. SPI, bitbang and the parallel port are unaffected.
- No mask-ready GDS: every ECC GDS holds standard cells and tile macros as LEF abstracts. DRC and LVS are iEDA's on abstracts and DEF connectivity, not GDS extraction, and the PDK's Calibre decks have not been run.
- No pad ring and no seal ring. With the parallel port on pads, about 86 signal pads plus power set the die edge; without it about 53.
- The `eFPGA_top` LEF names its supply pins `vdd_stripe_generate` and `vss_stripe_generate`, the pin names the floorplan gave the top-level PDN, and its Liberty holds 2 timing arcs for 166 pins.
- 38,744 to 48,386 slew and capacitance violations per full-chip STA corner.
- iLVS on `eFPGA_top` reports 278 power opens on the tiles' abutment-fed supply pins.
- No block RAM and no multi-port storage. `FABULOUS_LC` has no LUT RAM because its truth table is written only by the configuration chain.
- The branch history carries three primitives this variant does not instantiate (`ICS55_SRAM_512x32_1RW` with its vendor Liberty, `IHP_SRAM_1024x32_1RW`, `RAM_32x4_2R_1W`). A plain `git archive` ships them, so they have to be stripped before release.
- Device programming (Section 2.6) and the post-silicon setup (Section 8.1) are plans, pending the MPW package and board information.
