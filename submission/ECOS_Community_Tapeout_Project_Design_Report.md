## 1. Project Overview

### 1.1 Project Summary

The design is an island-style embedded FPGA generated by FABulous and hardened on ICS55 for an OpenECOS MPW die. The array `eFPGA` is a 13 × 12 grid of 151 hard tiles of 12 types, abutted into a 947.0 × 884.8 µm block, with the features of Section 1.2. The hardened top level `eFPGA_top` adds the configuration controller in a 999.0 × 912.6 µm block that needs 27 of the MPW's 36 pads.

Each tile type is hardened standalone by ECC to a routed macro. The array is assembled by abutment, so its 32,404 tile-to-tile nets connect through coincident pins and the `eFPGA_top` run routes only the 3,189 nets of the controller, the IO and the configuration buses.

The RTL, the 12 tile types and `eFPGA_top` are hardened and signed off on ECC abstracts (Section 6.3). An RTL bitstream simulation runs a counter on the fabric (Section 5.3). Outstanding are a mask-ready GDS, the pad ring and seal ring and a timed user design. Block RAM exists only in the `bram` variant.

### 1.2 Main Features

| Feature | Description | Implemented in this tapeout? |
|---|---|---|
| Logic cells | 800 `FABULOUS_LC`, 8 per `LUT4x8_ha` tile, each a LUT4 with flip-flop and carry chain | Yes |
| Hard multiply-accumulate | 5 `MACC_8x8_20`, 8 × 8 multiply into a 20-bit accumulator with carry in and out, one per two core rows | Yes |
| User IO | 10 bidirectional bits on `A_IN_top`, `A_EN_top` and `A_OUT_top`, one per `E_IO` tile on the east edge | Yes |
| Global clock network | 4 `GBUF` global clocks in `SW_term`, buffered at every tile hop (Section 2.5) | Yes |
| Frame-based configuration | 69,746 configuration latches (synthesis) written one frame at a time (Section 2.2) | Yes, all 12 rows including the two terminator rows |
| Full and partial reconfiguration | A partial bitstream writes any subset of frames while the rest of the fabric keeps running | Yes by construction of the frame addressing; not yet demonstrated in simulation |
| Configuration controller | `fabric_config` (fabulous-fabrics `7223ee9`) behind `config_frontend`, which merges UART, bitbang and SPI loaders | Yes, hardened in `eFPGA_top` |

### 1.3 Design Highlights and Use Cases (Optional)

Abutment bounds each tile run to at most 3,777 instances (`MACC`) and the top run to 3,150 standard cells around 151 fixed macros, against one flat run of 238,579 instances. On one `LUT4x8_ha`, 614 configuration latches take 39.6% of the die and 345 `MUX4` plus 32 `MUX2` routing switches 33.3%, so these set the logic density. The fabric reaches 955 logic cells per mm² (95.5% core utilisation) of array and 877 per mm² of `eFPGA_top`.

## 2. Design Description

### 2.1 System Architecture

`flow cli integrate` (`flow/topwrap.py`) generates `eFPGA_top` as a flat netlist of 151 tile macros and the configuration logic (`build/nobram/top/rtl/eFPGA_top.v`), with the ports of the hierarchical `fabrics/nobram/Fabric/eFPGA_top.v`. The grid is set by `fabrics/nobram/fabric.csv`.

| Column | Width (µm) | Tile types, top to bottom |
|---|---:|---|
| 0 | 28.8 | `NW_term`, `W_term` × 10, `SW_term` |
| 1–5 | 82.6 each | `N_term`, `LUT4x8_ha` × 10, `S_term` |
| 6 | 70.8 | `N_term_MACC`, `MACC` supertile × 5, `S_term_MACC` |
| 7–11 | 82.6 each | `N_term`, `LUT4x8_ha` × 10, `S_term` |
| 12 | 21.4 | `NE_term`, `E_IO` × 10, `SE_term` |

Core rows are 84.0 µm and terminator rows 22.4 µm. Each tile holds its BELs, a switch matrix and its configuration latches. Routing wires of span 1, 2, 4 and 6 cross each seam. `FrameData` (384 bits, 32 per row) enters on the west edge and `FrameStrobe` (260 bits, 20 per column) on the south edge. `W_term`, `N_term` and `S_term` are the classic library's `W_IO`, `N_IO` and `S_IO` with the `IOBUF` BEL removed, on the same dies so every seam pin stays in place.

In `eFPGA_top` the array's lower-left corner is at (50.0, 24.6) µm. The controller occupies a 48 µm west channel and a 22.4 µm south strip, with the array one 1.4 µm row above the strip.

The BELs are FABulous primitives (`FABULOUS_LC`, `MACC_8x8_20`, `IOBUF`, `GBUF`, `SYS_RESET`) and the tiles are the classic library of `FPGA-Research/fabulous-tiles` at `5809cdf`. No other third-party IP is instantiated (Section 11.2).

### 2.2 Operation

After `resetn` is released a host streams 32-bit words into one loader, which `config_frontend` takes in the priority UART, bitbang, SPI. Its 32-bit parallel input is tied low because its 33 pins do not fit the pad budget. `fabric_config` decodes the stream (Section 2.4) and pulses the `FrameStrobe` of the addressed frame, whose latches capture `FrameData`.

A frame is 32 bits in every row of one column. Each tile holds up to 20 frames (640 bits), of which `LUT4x8_ha` uses 614. A partial bitstream carries only the frames being changed. The user clock is separate from `CLK`, so logic outside those frames keeps running, while the user design must hold the rewritten region idle or in reset because its latches are transparent during `FrameStrobe`.

In user mode the configured fabric implements the user circuit, clocked as in Section 2.5. Cycle counts are set by that circuit.

### 2.4 Register or Command Definitions (Optional)

There are no memory-mapped registers. The fabric takes a FABulous bitstream of 32-bit words, decoded as below (from the loader and `fabric_config` sources in `Fabric/`).

| Address/Command | Name | Access | Reset value | Bit-field definition | Access side effects |
|---|---|---|---|---|---|
| `00 AA FF` + command byte | UART header | W | N/A | Command bit 7 selects hex (1) or binary (0) mode in the default auto mode | Starts a UART load; `ComActive` goes high |
| `0xFAB0_FAB1` | Start word | W | N/A | Fixed pattern | Moves `fabric_config` from idle to header; clears `Configured`; `ConfigBusy` goes high |
| Header word | Frame select | W | N/A | Bits [19:0] one-hot frame, bits [31:27] column, bit 20 desync flag | Selects one frame in one column; the next 12 words are its data |
| Frame data words | Frame data | W | N/A | 32 configuration bits for one row, row 11 first and row 0 last | After the 12th word the column's `FrameStrobe` pulses and the latches capture the frame |
| Header with bit 20 set | Desync | W | N/A | Bit 20 set | Returns `fabric_config` to idle, sets `Configured`, ends configuration |
| Bitbang control `0xFAB1` / `0xFAB0` | Bitbang on/off | W | N/A | 16-bit control word shifted on `s_clk` falling edges | `0xFAB1` latches the 32 data bits shifted on rising edges as one word; `0xFAB0` releases the port |
| SPI word | SPI data | W | N/A | 32 bits shifted in on `spi_sck` rising edges while `spi_cs_n` is low | Each complete word enters the stream |

The FABulous header `00AAFF01000000010000000000000000FAB0FAB1` lets a `.bit` file go unchanged over UART in binary mode or word by word over bitbang or SPI.

### 2.5 Clocks and Resets

`CLK` clocks the configuration logic only and is constrained at 10 ns (100 MHz, `fabric.frequency_mhz` in `Fabric/ecc_config.toml`). The UART divisor `ComRate` keeps its default of 217, which gives 115,200 baud at 25 MHz and 458,716 baud at 100 MHz; 115,200 baud at 100 MHz needs `ComRate` = 867. Bitbang and SPI do not depend on the `CLK` frequency.

The fabric has no clock port because `fabric.csv` sets `DisableUserCLK`. The user clock enters on the `SYS_RESET_RESET_top` pad, whose `SYS_RESET` BEL in `SW_term` connects only to the four `GBUF` inputs. It leaves the `GBUF` BELs on `E_GBUF` wires along the bottom row and `N_GBUF` wires up every column, with one clock buffer per tile hop. The `GBUF` inputs can also take fabric routing through the `S_term` and `W_term` feed wires, allowing up to four global nets. The user-mode clock frequency is unmeasured.

Minimum reset duration, reset release requirements and power-up sequencing are not specified: [to be taken from `fabric_config` and the MPW board's reset circuit].

### 2.6 Device Programming

Device programming is a plan pending the MPW package and test-board information. It reuses the bring-up flow of the wafer.space gf180mcu FABulous FPGA, `github.com/mole99/wsrun1-fpga-bringup` (`81a9a99`, Apache-2.0), which compiles designs with Yosys `synth_fabulous`, `nextpnr-generic --uarch fabulous` and the FABulous bitstream generator and loads them from an RP2040 Raspberry Pi Pico on MicroPython. Its `Makefile` flow, bitstream format, Pico file layout and generic test designs (`counter`, `passthrough`, `all_ones`, `all_zeros`) carry over. These parts are replaced.

1. The nextpnr model and bitstream specification from `fabrics/nobram/.FABulous/` (`pips.txt`, `bel.v3.txt`, `bitStreamSpec.bin`).
2. The IO constraints, already in place as `fabrics/nobram/user_design/pads.pcf` on the 10 `IOBUF` BELs, `iobuf_map.v` for the `-iopad` cells and a clock taken by instantiating `SYS_RESET` at `X0Y11.E` into a `GBUF`, as `top_wrapper.v` does.
3. The techmaps, without the register-file and SRAM mappings.
4. The Pico upload routine's pin set (`spi_cs_n`, `spi_sck`, `spi_mosi`, with `ConfigBusy` and `Configured` as status, against gf180's `FPGA_MODE`, `FPGA_BUSY`, `CS_N`, `SCLK`, `MOSI`); the protocol is unchanged.
5. The Pico pin assignment, which depends on the MPW test board.

### 4.6 Single Entry Point and Reproducibility

The build runs as five stages, each stopping at the first failure.

    task plan VARIANT=nobram        # size every tile and place every pin, writes build/nobram/fabric_plan.json
    task check VARIANT=nobram       # test the plan's wiring properties, no EDA tool
    task harden VARIANT=nobram      # one ECC run per tile type, synthesis to macro
    python3 -m flow.cli --variant nobram integrate   # harden eFPGA_top around the fixed tiles
    flow/sta/prepare.sh build/nobram pdk && flow/sta/run.sh build/nobram pdk   # full-chip OpenSTA, six corners

Hardening all 12 tile types took [time] on 2026-10-17; the three terminator types added on 2026-10-19 took 5 minutes at three jobs. The integrate run took 63 minutes on 2026-10-20, 58 of them from RCX through Harden. Logs go to `build/nobram/logs/`. Full-chip OpenSTA takes about 8.5 minutes and 2.7 GB per corner.

Five steps cannot be reproduced from a clean checkout today.

1. ECC `main` at `14be467` needs two uncommitted edits, a Nix flake override for boost and a `YOSYS_TECHMAP_FILES` block in `yosys_synthesis.tcl` (ecc#302).
2. RTL and pin orders need the two FABulous checkouts of Section 4.2.
3. The PDK liberty and GDS come from a GitHub release fetched by `make` in `pdk/`.
4. The bitstream simulation needs Yosys 0.62 (Section 5.1).
5. The gitignored `fabrics/nobram/.FABulous/` (`pips.txt`, `bel.v2.txt`, `bitStreamSpec.bin`) is regenerated by FABulous `c0ca476` with `load_fabric`, `gen_model_npnr` and `gen_bitStream_spec`.

### 4.8 Versioning, Compatibility, and Maintenance

The current version is v3.0 at `f82fb9a`, which replaces 30 IO tiles with terminators without changing any existing tile. ## 5. Design Verification

### 5.1 Verification Environment

1. `task check` tests without any EDA tool that every seam link declared in `Fabric/eFPGA.v` meets at one coordinate on both tiles.
2. Per-tile ECC signoff runs iEDA DRC, iLVS of routed DEF connectivity against the netlist and 13-corner iSTA.
3. The `eFPGA_top` run refuses a tile whose LEF pins differ from the netlist ports, fixes all 151 tiles at their planned coordinates and runs the same checks.
4. Full-chip OpenSTA reads the `eFPGA_top` netlist written from the filler DEF (the only view with the tile-to-tile nets), the 12 tile netlists and per-instance tile SPEF at six corners.
5. A bitstream simulation loads `sequential_16bit_en` into the `eFPGA_top` RTL over SPI and compares all 10 IO bits against the design simulated directly. The flow is Yosys 0.62 `synth_fabulous` (0.68 needs `-lut`, `-ff` and `-cells-map`, which the flow does not pass), `nextpnr-generic --uarch fabulous`, FABulous `bit_gen` and Icarus Verilog, run by `task VARIANT=nobram WAVEFORM_TYPE=vcd YOSYS_PATH=<yosys 0.62> build-test-design run-simulation` in `Test/`. It shifts 4,096 words (the bitstream padded to `MAX_BITBYTES`) with `spi_sck` at a quarter of the 1 MHz clock, 128 cycles per word, over a 524,531-cycle run whose VCD `+waveform_depth=1` keeps to 19.6 MB.
6. A cocotb 2.0.1 test on Icarus (`Test/config/test_config_frontend.py`) streams a bitstream through each of the UART, bitbang, SPI and parallel loaders and checks the words arrive in order; the SPI case also checks that a 7-bit fragment yields no word.

### 9.3 Value to the Open-Source Community

To the best of the authors' knowledge, this project is the first fully open FPGA taped out on the open ICS55 55 nm process. Every layer of it is open. FABulous generates the fabric, the tiles come from the open fabulous-tiles library, and ECC synthesises, places, routes and signs off every tile and the top level on the open ECOS PDK. The project fills a gap in the open 55 nm ecosystem and adds a complete, verified programmable-logic example to the open-source chip ecosystem built around the ECOS platform.

The project provides reusable IP for this process node. The 12 hardened tile types have frozen dies, fixed pin orders and a PDN that joins by abutment. A later project can take the hardened `eFPGA_top` as one block, or re-abut the same tiles into a fabric of the size its own die allows without hardening anything again. The baseline specification, deliverables and acceptance status that make this reuse possible are set out in Sections 4.3, 4.5 and 4.7.

The project also lowers both the threshold and the risk of chip design. A custom ASIC is fixed at fabrication, so a design error or a change in project requirements means another tapeout. Logic mapped onto this fabric is corrected or changed after fabrication by loading a new bitstream, and partial reconfiguration changes one region while the rest keeps running. A research group that needs custom hardware for its own scientific work, such as an experimental accelerator, an instrument or sensor interface, or a teaching platform, can use the fabric as delivered or generate a custom fabric for its application from the same open flow at this node.

By opening the complete path from fabric generation to signed-off layout, the project makes chip design accessible to more universities, research teams and individual developers. It supports open sharing, collaborative development and self-directed innovation across the open-source chip ecosystem at 55 nm.

#### 9.3（中文版）开源社区价值

据我们所知，本项目是首个在开放的 ICS55 55 纳米工艺上流片的全开源 FPGA。项目从架构到版图全链条开源：FPGA 架构由 FABulous 生成，逻辑单元（tile）来自开源的 fabulous-tiles 库，每一种 tile 以及顶层均在开源的 ECOS PDK 上由 ECC 完成综合、布局、布线与签核。本项目填补了开放 55 纳米工艺生态在可编程逻辑方面的空白，为以 ECOS 平台为核心的开源芯片生态贡献了一个完整且经过验证的可编程逻辑实例。

本项目为该工艺节点提供可复用的 IP。12 种已完成物理实现的 tile 具有固定的尺寸和引脚顺序，其供电网络通过拼接（abutment）即可直接连通。后续项目既可以将已完成物理实现的 `eFPGA_top` 作为一个整体模块直接集成，也可以根据自身芯片面积，将同一套 tile 重新拼接为不同规模的 FPGA，无需重新进行物理实现。支撑上述复用的基线规格、交付物与验收情况详见第 4.3、4.5 和 4.7 节。

本项目同时降低了芯片设计的门槛与风险。定制 ASIC 一经流片，功能即被固定；一旦出现设计错误或项目需求发生变化，就必须重新流片。而映射到本 FPGA 上的逻辑，在芯片制造完成后仍可通过加载新的比特流进行修正或更改；借助部分重配置功能，还可以在其余逻辑持续运行的同时，仅对其中一个区域进行更新。需要为自身科研工作定制硬件的研究团队，如开发实验性加速器、仪器或传感器接口以及教学平台，既可以直接使用本 FPGA，也可以基于同一套开源流程，在该工艺节点上生成面向自身应用的定制化 FPGA。

通过开放从 FPGA 架构生成到签核版图的完整链路，本项目让更多高校、科研团队和个人开发者能够参与芯片设计，助力 55 纳米开源芯片生态的开放共享、协同发展与自主创新。

### 9.4 Suggestions for the Platform and Flow

1. A hook for a user techmap before ECC's `flatten` (ecc#302), without which FABulous `my_buf` buffers become net aliases.
2. A tagged ECC release with the file-driven IO placer (`io_placer.mode = "file"`), which is on `main` only and not on `v0.1.0-alpha.12`.
3. Harden outputs carrying the routed layout and port timing; ECC writes `eFPGA_top`'s GDS as its LEF abstract with a 2-arc timing model.
4. A way to mark abutment-connected nets in iRT. On the 122-tile `bram` fabric 27,390 such nets drove the shape database to 49 GB before routing.
5. A flag to stream full standard-cell layouts into iEDA's GDS, which now holds LEF abstracts.
6. Escaping of `$` in iRCX SPEF and netlist names, which OpenSTA rejects.
7. Public MPW die-size, pad-ring and seal-ring rules, and a seal ring in the PDK.

## 10. Lessons Learned and Future Work (Optional)

### 10.1 Lessons from Design and Verification

`task check` and the stale-die guard in `harden` refuse a broken or stale plan in seconds instead of after a full harden. DreamPlace detailed placement decides routability on the dense tiles; without it `LUT4x8_ha` at 0.93 core utilisation oscillated between 2,134 and 2,643 violations over nine detailed-routing iterations. With it, violations went 687, 72, 21, 3, 0. ABC `AREA 5` gives 5,817.0 µm² on `LUT4x8_ha` against 5,882.0 µm² for the default `DELAY 4` (2026-09, earlier toolchain), which lets the 82.6 µm die route clean.

Per-tile STA cannot see the global clock. Each tile passed the `GBUF` clock through as a wire, so after abutment each global clock was one net of fanout 345 driven by one XOR, which only full-chip STA with per-instance tile SPEF exposed; one buffer per tile hop fixed it. Likewise, cell sizing in synthesis alone leaves drive closure to post-placement repair (Section 6.3).

### 10.2 Physical Implementation Issues

1. **LUT column width.** The `LUT4x8_ha` routing floor is 82.6 µm. At 81.8 µm placement reaches 0.9888 of the placeable area and three DRC violations remain after nine detailed-routing iterations.
2. **Boundary buffers.** ECC synthesis flattens every FABulous `my_buf` into a net alias. A techmap onto `BUFX1H7L`, with a mux map onto `MUX4X1H7L` and `MUX2X1H7L`, keeps the 288 buffers per tile for about 1% of cell area (uncommitted ECC edit).
3. **Top-level routing.** The tile-to-tile nets are connected by geometry only in the DEF. A planned alternative separates the tiles by a 1.4 µm gap with one straight pre-routed wire per seam net and bridged power stripes. The double-height `MACC` breaks this on its upper half and needs a re-harden at 168 µm plus the gap, or iRT jogs on those nets.
4. **Global placement on the top.** Legalise-only placement piles every standard cell into one corner; global placement converges only with `place.target_overflow = 0.15`.
5. **Timing.** No user-mode clock path has been timed (Section 6.3).

### 10.3 Planned Improvements

The next revision should produce a mask-ready GDS with the pad ring and seal ring, demonstrate partial reconfiguration in simulation, match `ComRate` to the 100 MHz `CLK` and time a routed user design across the tiles' extracted Liberty. It should also fix the ECC build so it needs no uncommitted edits.

## 11. Additional Information

### 11.1 Known Limitations

- User-mode Fmax is unmeasured; the tile-level `sta_frequency_mhz` 40 on `LUT4x8_ha` comes from a loop through the unconfigured switch matrix.
- Only `GBUF` A is shown to work. A counter clocked through `GBUF` C stays X in RTL simulation although nextpnr routes the clock to every flip-flop. `GBUF` B and D are untested. The cause is not established.
- Simulation is RTL only, with no gate-level or partial-reconfiguration run.
- `ComRate` = 217 is mismatched to the 100 MHz `CLK` (Section 2.5).
- No mask-ready GDS, pad ring or seal ring; the PDK's Calibre decks have not been run (Sections 5.2 and 7).
- 10 user IO bits in total, all in column 12.
- Row 0 configuration is shown only by routed nets, not in simulation.
- The `eFPGA_top` Liberty holds 2 timing arcs for 43 pins.
- 278 power opens in `eFPGA_top` iLVS (Section 6.3).
- No block RAM or multi-port storage; `FABULOUS_LC` has no LUT RAM because only the configuration chain writes its truth table.
- The branch history carries three primitives this variant does not instantiate (`ICS55_SRAM_512x32_1RW` with its vendor Liberty, `IHP_SRAM_1024x32_1RW`, `RAM_32x4_2R_1W`), which a plain `git archive` ships, so they must be stripped before release.
- Device programming and the post-silicon setup are plans (Sections 2.6 and 8.1).
